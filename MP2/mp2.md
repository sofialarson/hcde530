C4 — APIs and Data Acquisition
My tool calls the Anthropic Claude API to interpret vague researcher descriptions and match them against verbatim transcript text. The API key is stored in a .env file that is listed in .gitignore and never committed to the repository — anyone cloning the repo must supply their own key. The system prompt sent to the API enforces strict rules: return only verbatim text, never paraphrase, respond in a fixed JSON schema that the tool then parses and filters client-side. I also went through two alternative API providers (Gemini, Groq) when each failed due to quota or authentication issues, reading their documentation and debugging the integration before ultimately switching back to Anthropic.

C7 — Critical Evaluation and Professional Judgment
Several times during development the AI returned output I had to catch and correct. The speaker detection regex initially returned 29 false positives because the pattern was too permissive; it was matching fragments of timestamps like "Speaker 1 0" as separate speakers. I diagnosed this by reading the raw matched output, identified that the non-greedy quantifier was the cause, and rewrote the pattern to anchor correctly on the double-space separator. I also caught that Claude was sometimes returning quotes with minor whitespace differences from the original transcript, which caused the jump-to-transcript feature to silently fail. I rewrote find_quote_char_offset to try six progressively fuzzier matching strategies rather than failing silently. Additionally, I added a score explanation banner to the UI specifically because I recognized that AI-generated match scores could be misread as precise measurements — the banner explicitly tells users scores are relative estimates, not absolute values.

C8 — Building and Deploying a Complete Tool
My MP2 is a Jupyter notebook-based tool for UX researchers that takes an interview transcript (pasted or uploaded as PDF or TXT), interprets a vague description of what the researcher is looking for, and returns ranked verbatim quotes from the transcript with match scores, key term highlights, timestamps, and speaker labels. It includes a speaker filter, a minimum score slider, a persistent quote library with drag-and-drop folders, and an export function. The biggest challenge I hit was that the FileUpload widget in ipywidgets 8.x returns data in a completely different format than earlier versions. I diagnosed it by inspecting the raw widget value and rewrote the file handler to match the actual data structure. If I were starting over I would scope the quote library as a separate cell from the start rather than trying to preserve its state across re-renders, which required a significant architectural change mid-build to split into two separate output areas.
